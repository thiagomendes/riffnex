# M2 analysis baseline: the bundled demo

> Measured by the test suite on CI (Linux: `MusicCoreTests`; iOS simulator: `AnalysisEngineTests`).
> Ground truth: `tools/fixtures/riffnex-demo.truth.json` (51 notes, 7 power chords, 96 BPM, E minor).
> Notes are scored like `mir_eval.transcription` (onset-only, ±50 ms, same MIDI pitch, maximum matching).

## Port fidelity

`NoteDecoder` is a Swift port of basic-pitch 0.4.0 `output_to_notes_polyphonic`. Fed the reference
model's activations (`Tests/Fixtures/demo-activations.bin`, generated by `tools/fixtures/make_golden.py`),
it reproduces the reference's output **exactly** (same start frame, end frame and pitch for every note)
for all three parameter sets tested:

| Config | Reference notes | Swift port |
|---|---|---|
| default (onset 0.5, frame 0.3, 11 frames, melodia) | 85 | 85, identical |
| guitar range (MIDI 40–88) | 74 | 74, identical |
| sensitive, no melodia (0.3 / 0.2 / 6) | 262 | 262, identical |

**Deliberate deviation:** frame → time uses the exact window geometry
(`(256·f − 188·⌊f/142⌋) / 22050`) instead of the reference's fitted constant, so timing does not drift
across 2 s windows. Covered by `BasicPitchTimingTests`.

## Notes

| Stage | Precision | Recall | F1 |
|---|---|---|---|
| Reference decoding (raw) | 0.41 | 0.69 | 0.51 |
| + RIFFNEX guitar clean-up (`NotePostProcessor`) | 0.66 | 0.90 | **0.76** |

Clean-up report on the demo: 85 decoded, 8 out of guitar range, 7 overtones suppressed, 23 onsets
moved back to their onset-activation peak, 70 kept.

What the remaining errors are: extra notes are mostly overtones that are louder than the 0.6 ratio
allows (kept on purpose so real octave doublings in power chords survive) and drum hits; missed notes
are mostly repeated notes whose onset the model did not mark.

## Chords, sections, quality

- Chords (truth beat grid): **16/16** chord beats correct (E5 G5 A5 C5 E5 G5 D5); **16/16** riff beats
  correctly left without a chord (single-line playing is not labeled as a chord).
- Sections (Music Understanding boundaries + RIFFNEX letters): `A` (riff), `B` (chords), `Final`.
- Quality report: `good`, no reasons. 23% of notes are low confidence.

## Core ML vs reference (iOS simulator, CI)

- The bundled `nmp.mlpackage` run through RIFFNEX's own windowing (AVAudioConverter decode, CPU) vs
  the reference ONNX model run on ffmpeg-decoded audio: mean absolute difference of the note
  activations is **0.0016** over 1 849 frames. The largest single difference is 0.79 and is isolated;
  it comes from the decoders differing at transients.
- The note F1 after the full on-device pipeline is **0.76**, the same as with the reference
  activations.
- Music Understanding works in the iOS 27.1 simulator: **96 BPM, Em**.
- Stage timings in the simulator (CPU only, CI Mac) for the 21.5 s demo:
  - decode 0.01 s
  - notes 4.0 s
  - Music Understanding 12.8 s, run in parallel with the notes
  - assembly 0.7 s

## M3 fingering (canonical cases, Linux CI)

- Demo riff: **49/51** recommended positions equal the positions the riff was written with.
- F barre chord: 1-3-3-2-1-1 with fingers index, ring, ring, middle, index, index (barre detected).
- G5–A5–C5: 6th- and 5th-string power-chord shapes (G5 = s0f3, C5 = s1f3).
- Two-octave E minor pentatonic: a single box with at most two hand shifts, and no open strings mixed
  in above the 4th position.

## Instrument separation (Demucs htdemucs_6s on Core ML)

- Conversion check (CI Mac, one 7.8 s segment): the Core ML core plus the reference iSTFT differs from
  PyTorch by at most 2.9% of the mix energy per source. fp16 and fp32 give the same figures.
- Swift pipeline vs the PyTorch `apply_model` reference on the full demo, comparing the per-source RMS
  envelope (0.25 s hops):

  | Source | Correlation | Level ratio |
  |---|---|---|
  | drums | 1.000 | 0.98 |
  | piano | 1.000 | 0.99 |
  | guitar | 1.000 | 1.00 |
  | bass | 0.997 | 1.00 |
  | vocals | 0.992 | 1.00 |
  | other | 0.61 (almost silent in the demo) | 1.07 |

- Speed in the iOS simulator with the CPU only: 21.5 s of audio in 95 s. The device figure comes from
  Diagnostics on the owner's iPhone.
- **Demucs hears the demo's synthesized guitar as piano** (99% of the pitched energy). That is why
  notes come from guitar + piano + other unless the guitar stem clearly dominates. On the demo, notes
  detected on the stems are a little worse than on the full mix: two chords come out as Em7/Am7
  instead of E5. The demo has no vocals, so separation cannot help it. Real songs with vocals are where
  it should help, and that still has to be measured.
